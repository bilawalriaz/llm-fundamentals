The Illustrated Transformer by Jay Alammar is the definitive visual walkthrough of the Transformer architecture introduced in "Attention Is All You Need" (Vaswani et al., 2017). This analysis provides an exhaustive examination of every component — from the mechanics of self-attention and the Q/K/V vector formulation, through multi-head attention and positional encoding, to the encoder-decoder architecture, residual connections, layer normalization, training with teacher forcing, and inference-time decoding strategies. Understanding this architecture is the prerequisite to every paper in this collection: it is the foundation upon which all modern LLMs are built.

1. Overview and Historical Context

Before Transformers, sequence-to-sequence tasks — machine translation, text summarization, dialogue generation — were dominated by Recurrent Neural Networks (RNNs), specifically Long Short-Term Memory (LSTM) and Gated Recurrent Unit (GRU) architectures. These models processed tokens sequentially: hidden state h_t depended on h_{t-1}, creating an inherently serial computation graph. This meant that for a sequence of length n, you needed O(n) sequential steps, making it impossible to fully parallelize across tokens. Even with techniques like bidirectional RNNs, the fundamental bottleneck remained: each position had to wait for the previous one.

The Transformer, introduced by Vaswani et al. in 2017, eliminated recurrence entirely and replaced it with self-attention — a mechanism that allows every token in a sequence to directly attend to every other token in a single computational step. This yields two transformative properties: (1) full parallelization across all positions during training, and (2) constant-depth pathways between any two tokens regardless of sequence length. The Illustrated Transformer provides the clearest visual and intuitive explanation of how this mechanism works, making it the essential reference for understanding the architecture that powers GPT, BERT, T5, LLaMA, and essentially every modern language model.

"The key innovation of the Transformer is that attention replaces recurrence — and that's what allows full parallelization across all positions in a sequence."

2. Self-Attention: The Core Mechanism

2.1 The Intuition

Self-attention answers a simple question for every token: "Which other tokens in this sequence are most relevant to me right now?" Unlike attention in the original seq2seq models (Bahdanau et al., 2014), which attended from the decoder to the encoder, self-attention operates within a single sequence — each token attends to all tokens in the same sequence, including itself. This allows the model to capture long-range dependencies without the vanishing gradient problem that plagued RNNs.

The mechanism works by transforming each input token embedding into three vectors: a Query (Q), a Key (K), and a Value (V). These are computed via learned linear projections of the input embeddings.

2.2 Query, Key, Value Vectors

For an input sequence of token embeddings X ∈ ℝ^{n×d_model}, where n is the sequence length and d_model is the embedding dimension (512 in the original Transformer), the Q/K/V projections are: 

Q = X · W_Q    where W_Q ∈ ℝ^{d_model × d_k}
K = X · W_K    where W_K ∈ ℝ^{d_model × d_k}
V = X · W_V    where W_V ∈ ℝ^{d_model × d_v}

The matrices W_Q, W_K, and W_V are learned parameters — they are not hand-crafted. Each projection is a linear transformation that maps the d_model-dimensional embedding into a d_k-dimensional (or d_v-dimensional) subspace. The intuition is:

  • Query (Q): "What am I looking for?" — represents what the current token is trying to find
  • Key (K): "What do I contain?" — represents what information this token broadcasts
  • Value (V): "What do I actually contribute?" — the actual content that gets passed along

The analogy is a library search: the Query is your search query, the Key is the book's label/index, and the Value is the book's content. You match your query against all keys to decide how much of each value to retrieve.

📐
Dimension Choices in the Original Transformer: With d_model = 512 and 8 attention heads, each head operates in d_k = d_v = 64 dimensions. The total computation across all 8 heads is equivalent to a single 512-dimensional attention, but with the benefit of learning 8 independent attention patterns. This connects to Paper 04: SmolLM2, which uses grouped-query attention (GQA) to reduce KV head count for inference efficiency.

2.3 Scaled Dot-Product Attention

The attention score between position i and position j is computed as the dot product of the query at position i with the key at position j: 

Attention(Q, K, V) = softmax(QKᵀ / √d_k) · V

Step by step:

1

Compute Scores

Calculate QKᵀ — a matrix of shape (n, n) where entry (i,j) is the dot product q_i · k_j. This measures how "compatible" each pair of positions is.

2

Scale

Divide by √d_k to prevent the dot products from growing too large in magnitude, which would push the softmax into regions with vanishing gradients.

3

Mask (Optional)

In the decoder, apply a causal mask: set scores for positions j > i to -∞ so the model cannot attend to future tokens.

4

Softmax

Apply softmax across each row to get attention weights that sum to 1. This creates a probability distribution over all positions.

5

Weighted Sum

Multiply the attention weights by the Value matrix. Each position's output is a weighted combination of all Value vectors, with weights determined by attention scores.

The scaling factor √d_k is critical. Without it, for large d_k, the dot products grow in variance, leading to extremely peaked softmax distributions that concentrate almost all probability mass on a single position. This makes gradients very small and training unstable. The variance of dot products of random vectors in d_k dimensions is approximately d_k, so dividing by √d_k normalizes the variance to approximately 1.

3. Multi-Head Attention

3.1 Why Multiple Heads?

A single attention head computes one attention pattern — one set of weights over all positions. But language requires attending to many different types of relationships simultaneously: syntactic dependencies (subject-verb agreement), coreference (pronouns referring to nouns), positional proximity, semantic similarity, and more. Multi-head attention addresses this by running multiple attention computations in parallel. 

MultiHead(Q, K, V) = Concat(head_1, ..., head_h) · W_O

where head_i = Attention(Q·W_Q_i, K·W_K_i, V·W_V_i)

In the original Transformer, h = 8 heads are used. Each head learns a different set of projection matrices W_Q_i, W_K_i, W_V_i, and consequently learns to attend to different types of relationships.

3.2 What Each Head Learns

Visualization of trained attention heads reveals specialization:

Research by Clark et al. (2019) analyzing BERT attention heads found that specific heads reliably encode specific linguistic relationships. Some heads attend to the previous token (positional bias), some attend to sentence boundaries, and others attend to semantically related content. This specialization emerges without explicit supervision — it is learned purely from the language modeling objective.

3.3 The Output Projection

After concatenating the outputs of all 8 heads, the result is a matrix of shape (n, h·d_v) = (n, 512). A final linear projection W_O ∈ ℝ^{h·d_v × d_model} maps this back to the model dimension, allowing the concatenated multi-head output to interact across heads. The total parameter count for a single multi-head attention layer is: 

Parameters = 4 × d_model²  (Q, K, V projections + output projection)
           = 4 × 512² = 1,048,576 ≈ 1M parameters per attention layer
🔗
Cross-references: This connects to Paper 03: Phi-1, where attention modifications (blocksparse attention in Phi-3) demonstrate that the basic attention mechanism can be specialized for efficiency. It also connects to Paper 04: SmolLM2, which uses grouped-query attention (GQA) — a variant where multiple query heads share key-value heads, reducing inference-time memory without significant quality loss.

4. Positional Encoding

4.1 The Problem: Permutation Invariance

Self-attention is permutation-invariant: if you shuffle the input sequence, the attention mechanism produces a correspondingly shuffled output, but the attention patterns themselves don't change. This means the model has no inherent notion of word order. "The cat chased the dog" and "The dog chased the cat" would produce identical attention patterns if only the token order were changed — the model needs explicit position information.

4.2 Sinusoidal Positional Encoding

The original Transformer uses fixed sinusoidal positional encodings, where each position pos and dimension i gets a value: 

PE(pos, 2i)   = sin(pos / 10000^{2i/d_model})
PE(pos, 2i+1) = cos(pos / 10000^{2i/d_model})

These encodings are added to the token embeddings before the first encoder layer. The key properties:

  • Unique per position: Each position gets a distinct encoding vector
  • Relative positions can be learned: PE(pos+k) can be represented as a linear function of PE(pos), so the model can learn to attend to relative distances
  • Generalizes to unseen lengths: Unlike learned position embeddings, sinusoidal encodings can extend to sequences longer than those seen during training
  • Frequency spectrum: Lower dimensions encode fine-grained positional information (high frequency), while higher dimensions capture broader patterns (low frequency)

The intuition behind the frequency spectrum: the first dimension (i=0) has period 2π, alternating rapidly between +1 and -1 for adjacent positions. The last dimension has period 2π × 10000, barely changing over thousands of positions. Together, they create a rich, multi-scale representation of absolute position — analogous to a binary counter where each bit flips at a different rate.

4.3 Learned Positional Embeddings

An alternative (used by BERT and GPT-2) is to learn position embeddings directly as parameters: a matrix E_pos ∈ ℝ^{L_max × d_model} where L_max is the maximum sequence length. These are learned during training and added to the token embeddings. The tradeoff:

ApproachAdvantageDisadvantage
SinusoidalGeneralizes to unseen lengthsMay be less expressive
LearnedCan capture complex patternsFixed max length, more parameters
Rotary (RoPE)Relative by construction, extends wellSlightly more complex implementation

Modern LLMs (LLaMA, Qwen, Mistral) have largely moved to Rotary Position Embeddings (RoPE), which encode relative position directly in the attention computation rather than adding position information to the input. This allows much longer context windows (128K+ tokens) without retraining.

5. Residual Connections and Layer Normalization

5.1 Residual Connections

Each sub-layer in the Transformer (attention or feed-forward) is wrapped with a residual connection: 

output = LayerNorm(x + Sublayer(x))

The residual connection adds the original input x directly to the sub-layer's output. This serves two critical purposes:

  • Gradient flow: During backpropagation, gradients can flow directly through the identity skip connection, bypassing the sub-layer entirely. This prevents vanishing gradients in deep networks.
  • Feature preservation: The model can learn to make small modifications to the input representation rather than completely rewriting it, which is easier to optimize.

5.2 Layer Normalization

Layer normalization normalizes the activations across the feature dimension for each token independently: 

LayerNorm(x) = γ · (x - μ) / √(σ² + ε) + β

where μ and σ² are the mean and variance computed across the feature dimension, and γ, β are learned scale and shift parameters. Layer normalization stabilizes training by ensuring activations have consistent statistical properties across layers. The original Transformer uses Post-LN (normalize after the residual addition), while modern models typically use Pre-LN (normalize before the sub-layer), which allows training deeper models more easily.

⚠️
RMSNorm vs LayerNorm: Modern LLMs (LLaMA, SmolLM2) have largely replaced LayerNorm with RMSNorm, which omits the mean-centering step and only normalizes by the root mean square. This is computationally cheaper and has been shown to work equally well in practice. See Paper 04: SmolLM2 for its use in a small-model context.

6. The Feed-Forward Network

After each attention sub-layer, a position-wise feed-forward network (FFN) is applied independently to each position: 

FFN(x) = ReLU(x · W_1 + b_1) · W_2 + b_2

The FFN expands from d_model to d_ff = 2048 (4× the model dimension in the original), applies a nonlinearity, then projects back down. This is essentially a two-layer MLP applied independently at each position. The expansion ratio (typically 4×) provides capacity for non-linear feature transformation.

The FFN is often described as the "memory" of the Transformer: while attention performs information routing (deciding which tokens to mix), the FFN stores and retrieves factual knowledge. Research by Meng et al. (2022) on knowledge editing found that factual associations are primarily stored in the FFN layers, suggesting a division of labor: attention = communication, FFN = storage.

7. Encoder-Decoder Architecture

7.1 The Encoder Stack

The encoder consists of 6 identical layers, each containing:

  1. Multi-head self-attention — every token attends to every other token (no mask)
  2. Position-wise FFN — independent transformation at each position
  3. Residual connections + layer normalization around each sub-layer

The encoder processes the entire input sequence in parallel, producing contextual representations where each token's embedding has been enriched by information from all other tokens. After 6 layers, the encoder output is a matrix ℝ^{n×d_model} that serves as the memory for the decoder.

7.2 The Decoder Stack

The decoder also has 6 identical layers, but each layer has three sub-layers instead of two:

  1. Masked multi-head self-attention: Identical to encoder self-attention, but with a causal mask that prevents position i from attending to positions j > i. This is essential for autoregressive generation — during training, each position should only see the tokens that came before it.
  2. Multi-head cross-attention: The Queries come from the decoder, but the Keys and Values come from the encoder output. This allows each decoder position to attend to all encoder positions, retrieving relevant information from the input.
  3. Position-wise FFN: Same as in the encoder.

The cross-attention mechanism is the bridge between input and output. For machine translation, it allows each word being generated to "look back" at all source words and decide which ones are relevant. The Keys and Values are computed from the encoder output (shared across all decoder layers), while the Queries are computed from the decoder's current state.

7.3 Decoder-Only Models

It's worth noting that most modern LLMs (GPT, LLaMA, Mistral, Qwen) use a decoder-only architecture — they drop the encoder and cross-attention entirely, using only masked self-attention and FFN layers. This simplification works because language modeling is inherently autoregressive: you predict the next token given all previous tokens, which only requires the causal (masked) self-attention that the decoder already has. The encoder-decoder structure is still preferred for tasks like translation where there are two distinct sequences (source and target).

"The decoder-only architecture became dominant because language modeling is fundamentally autoregressive — you only need to predict the next token given previous tokens, which masked self-attention handles perfectly."

8. Training: Teacher Forcing and Loss

8.1 Teacher Forcing

During training, the Transformer uses teacher forcing: the decoder receives the ground-truth target sequence (shifted right by one position) as input, rather than its own predictions. For the target sequence y_1, y_2, ..., y_m, the decoder input is <bos>, y_1, y_2, ..., y_{m-1} and the model is trained to predict y_1, y_2, ..., y_m at each position.

The training loss is the standard cross-entropy loss applied to the next-token prediction at each position: 

L = -Σ_{t=1}^{m} log P(y_t | y_{<t}, X)

This formulation means all positions are predicted simultaneously — the entire target sequence is processed in one forward pass, and the loss is the average negative log-likelihood across all positions. This is a massive computational advantage over RNNs, which required sequential processing.

8.2 Training Details

The original Transformer was trained on the WMT 2014 English-German translation task (4.5M sentence pairs) and WMT 2014 English-French task (36M sentence pairs). Key hyperparameters:

8.3 Learning Rate Schedule

The Transformer uses a distinctive learning rate schedule with linear warmup followed by inverse square root decay: 

lr = d_model^{-0.5} × min(step^{-0.5}, step × warmup_steps^{-1.5})

The learning rate increases linearly from 0 to its maximum during the first 4,000 steps (warmup), then decreases proportionally to the inverse square root of the step number. This schedule was found to be crucial for stability — starting with a high learning rate causes divergence, while no warmup leads to slow convergence. This warmup + decay pattern has become standard in transformer training.

9. Inference: Decoding Strategies

9.1 Autoregressive Generation

At inference time, the model generates text token by token. For each new token:

1

Feed Input

Pass the prefix (all previously generated tokens) through the encoder (for encoder-decoder) or directly through the decoder (decoder-only).

2

Compute Dist

The final layer produces logits for each token in the vocabulary. Apply softmax to get a probability distribution.

3

Sample/Select

Choose the next token using greedy decoding (argmax), beam search, or sampling (top-k, top-p/nucleus).

9.2 Greedy Decoding vs. Beam Search

Greedy decoding selects the highest-probability token at each step. It's fast but globally suboptimal — the locally best choice may lead to a worse overall sequence.

Beam search maintains k hypotheses (beams) simultaneously, expanding each by all possible next tokens and keeping only the top k most probable complete sequences. For translation, beam search with k=4 or k=8 typically improves over greedy decoding. However, for open-ended generation (stories, dialogue), beam search can produce degenerate, repetitive text — sampling methods (temperature scaling, top-k, nucleus sampling) are preferred.

9.3 Parallelization Advantage

The key computational advantage over RNNs: during training, all positions are computed in parallel. For an RNN processing a sequence of length n, you need O(n) sequential steps. For a Transformer, the self-attention computation is O(n²) in total FLOPs, but each operation is independent and can be executed in parallel on GPU/TPU hardware. In practice, for sequences up to a few thousand tokens, Transformers are dramatically faster to train than RNNs because of this parallelism.

The quadratic attention cost O(n²) becomes a limitation for very long sequences (100K+ tokens). This has motivated research into efficient attention mechanisms: sparse attention (Longformer, BigBird), linear attention (Linformer, Performer), and FlashAttention (Dao et al., 2022), which doesn't reduce FLOPs but dramatically improves memory efficiency by computing attention in blocks that fit in GPU SRAM. This connects to Paper 03: Phi-1, which uses FlashAttention for efficient training, and Paper 04: SmolLM2, which also leverages FlashAttention for small-model efficiency.

10. Ablations and Design Decisions

Why not use a single large attention head instead of multiple small ones?
Ablations in the original paper show that reducing the number of heads while keeping the total dimension constant degrades performance. Multiple heads allow the model to attend to different types of relationships simultaneously. With a single head of dimension d_k = 512, the model would compute one attention pattern per position — it would have to compromise between attending to syntactic structure, semantic similarity, and positional proximity. With 8 heads of dimension 64 each, these patterns can be learned independently and combined. The computational cost is identical (same total matrix multiplications), but the representational capacity is greater.
Why is the scaling factor √d_k and not something else?
The scaling factor corrects for the variance growth of dot products. For random vectors q, k ∈ ℝ^{d_k} with entries drawn from a distribution with mean 0 and variance 1, the expected value of q·k is 0 but the variance is d_k. Without scaling, for large d_k, the dot products have large magnitude, pushing the softmax into regions where gradients are extremely small (the "softmax saturation" problem). Dividing by √d_k normalizes the variance back to approximately 1, keeping softmax in a well-behaved regime. This is analogous to Xavier initialization for neural networks.
Why 6 layers in both encoder and decoder?
The original paper ablated depth: 1, 2, 4, 6, and 8 layers. Performance improved significantly from 1→2→4 layers, with diminishing returns beyond 6. Deeper models also required more training data and compute to avoid overfitting. The 6-layer choice was a practical balance between performance and training cost on the available hardware (8 NVIDIA P100 GPUs). Modern LLMs use much deeper models (32-128 layers) because they train on vastly more data, but the principle of diminishing returns with depth still holds.
Why Pre-LN vs Post-LN?
The original Transformer uses Post-LN: LayerNorm(x + Sublayer(x)). However, this makes training very sensitive to initialization and learning rate — deep Post-LN models often diverge. Xiong et al. (2020) showed that Pre-LN (x + Sublayer(LayerNorm(x))) provides much more stable training because the gradient norm is preserved through the residual path without being disrupted by layer normalization. Pre-LN is now standard in virtually all LLMs. The tradeoff is that Post-LN models may achieve slightly better final performance when they do converge, but the stability advantage of Pre-LN makes it practically superior.

11. Limitations

The Illustrated Transformer, while exhaustive as a visual guide, has several limitations worth noting:

  • Focus on original architecture: It describes the 2017 Transformer, not the many variants that have since emerged (decoder-only, encoder-only, sparse attention, GQA, RoPE, etc.).
  • No coverage of modern modifications: Topics like FlashAttention, grouped-query attention, rotary embeddings, sliding window attention, and mixture-of-experts are not covered.
  • Translation-centric: The examples focus on machine translation, while the vast majority of modern Transformer usage is language modeling, code generation, and multimodal tasks.
  • Compute analysis: The blog doesn't deeply analyze the computational complexity tradeoffs between attention (O(n²)) and recurrence (O(n)), which are crucial for understanding scalability limits.
  • No training recipes: Modern training involves data mixtures, curriculum learning, and scaling laws that go far beyond the original paper's simple setup.
