ZEPHYR: Direct Distillation of LM Alignment

Tunstall et al. (HuggingFace)
arXiv:2310.16944
October 2023
Paper

Zephyr-7B is a 7B parameter model that surpasses Llama2-Chat-70B on MT-Bench through a three-stage automated pipeline: distillation-SFT on UltraChat (1.47M conversations filtered to 200K), AI feedback on UltraFeedback (64K samples with GPT-4 scoring), and distillation-DPO with β=0.1 for 3 epochs. The entire pipeline uses AI-generated data with zero human annotation, requires only 16 A100 GPUs for 2-4 hours per stage, and demonstrates that SFT is a necessary prerequisite for DPO to function properly.

The Three-Stage Pipeline

Zephyr's alignment pipeline is a refinement of the standard SFT → DPO sequence, with each stage carefully optimized for data quality and training efficiency. The key innovation is using AI-generated data at every stage, eliminating the need for human annotation entirely.

1

Distillation-SFT (dSFT)

Train on 200K filtered conversations from UltraChat (originally 1.47M). Data generated by GPT-3.5-turbo. 1 epoch. Establishes conversational format and instruction-following.

2

AI Feedback (AIF)

Generate 4 candidate responses per prompt from the dSFT model. Score all candidates with GPT-4. Keep best and worst as chosen/rejected pairs. 64K preference pairs.

3

Distillation-DPO (dDPO)

Apply DPO ([Paper 10]) with β=0.1, 3 epochs, learning rate 5e-7. No reference model needed — the dSFT model serves as πref.

Stage 1: Distillation-SFT (dSFT)

UltraChat is a large-scale dataset of multi-turn conversations generated by GPT-3.5-turbo. The original dataset contains 1.47M conversations, but the authors apply quality filtering to retain only 200K — a 7:1 reduction. This filtering step is critical: the original dataset contains many low-quality, repetitive, or off-topic conversations that would degrade the model's behavioral pattern. This connects directly to [Paper 08] (LIMA), which demonstrates that data quality dominates quantity for alignment.

The dSFT model is trained for exactly 1 epoch on the filtered dataset. The authors find that more epochs lead to overfitting on the training data, which paradoxically doesn't hurt benchmark performance but degrades the model's ability to generalize to unseen prompt types.

Stage 2: AI Feedback (AIF)

The AIF stage generates preference data without any human annotation: 

AIF Data Generation Process:

1. Take the 64K prompts in the UltraFeedback dataset
2. For each prompt, generate 4 candidate responses
   using the dSFT model (temperature 0.7)
3. Score all 4 responses with GPT-4
4. Select:
   - Best response (highest GPT-4 score) → chosen (y_w)
   - Worst response (lowest GPT-4 score) → rejected (y_l)
5. Result: 64K (prompt, chosen, rejected) triples

The use of 4 candidates (rather than 2) provides richer signal: GPT-4 can rank all 4 and select the extreme pairs, which produces cleaner preference data than binary comparison. The chosen/rejected split is maximally informative — the best and worst responses differ the most in quality, making the DPO signal strongest.

Stage 3: Distillation-DPO (dDPO)

The dDPO stage applies the DPO loss ([Paper 10]) with specific settings optimized for the Zephyr pipeline: 

dDPO Training Configuration:

Base model:       Zephyr-dSFT (from Stage 1)
Reference model:  Zephyr-dSFT (same as base, frozen)
Loss:             DPO ([Paper 10])
β:                0.1 (strong KL penalty)
Learning rate:    5e-7
Epochs:           3
Batch size:       64
Warmup:           3% of steps
Optimizer:        AdamW (β₁=0.9, β₂=0.95)
Hardware:         16 × A100 80GB GPUs
Training time:    a few hours
💡
Why β = 0.1? The choice of β = 0.1 (matching the DPO paper's recommendation) reflects a conservative approach: keep the policy close to the reference (dSFT) model. This prevents the DPO stage from "forgetting" the behavioral patterns learned during SFT. Higher β values (e.g., 0.5) allow more divergence from the reference, which can lead to reward hacking on the GPT-4 preferences.

Critical Ablations

Finding 1: SFT Is Required Before DPO

The most important ablation demonstrates that DPO cannot be applied directly to the base model without an SFT stage:

ConfigurationMT-BenchNotes
Base (Mistral-7B)4.76No alignment
DPO only (no SFT)4.76DPO without SFT = no improvement!
dSFT → dDPO7.34Full pipeline works
dSFT only (no DPO)7.00SFT alone is strong
⚠️
Critical finding: DPO applied directly to the base model (without SFT first) achieves the same MT-Bench score as the untrained base model (4.76). This means DPO alone cannot establish the behavioral foundation — SFT must come first. This is because the base model's response distribution is so different from the assistant-like distribution assumed by the preference data that DPO has nothing useful to learn. The SFT stage shifts the model's output distribution into the right "neighborhood" where DPO can then refine preferences.

Finding 2: Overfitting Is Not Harmful

A surprising finding is that even when DPO overfits to the training preferences (100% training accuracy after 1 epoch), the model's quality on held-out benchmarks doesn't degrade: 

Zephyr-7B after dDPO (held-out benchmarks):

  MT-Bench:    7.34
  AlpacaEval:  90.6%

Key: the paper reports that DPO overfitting to the
preference data does not degrade held-out performance.

This is fundamentally different from overfitting in supervised learning. In DPO, "overfitting" means the model perfectly ranks chosen over rejected in the training set. But this preference pattern generalizes — the model learns a consistent behavioral template (prefer helpful, detailed, accurate responses) that applies to unseen prompts as well. The overfitting is in the ranking function, not in specific content.

The best performance comes from a specific combination of SFT and DPO epochs:

More SFT epochs actually hurt the final DPO performance, likely because the model overfits to the SFT data format and loses the flexibility that DPO needs to refine preferences. The sweet spot is 1 SFT epoch (enough to establish the behavioral template) followed by 3 DPO epochs (enough to refine preferences without overfitting to the training distribution).

Training Infrastructure

The entire Zephyr pipeline is remarkably efficient in terms of compute: 

Training Infrastructure:

Hardware:     16 × NVIDIA A100 80GB GPUs
Framework:    TRL (Transformer Reinforcement Learning)
Parallelism:  DeepSpeed ZeRO-3 (full parameter sharding)
Attention:    FlashAttention-2 (memory-efficient attention)
Precision:    BF16 mixed precision

Stage 1 (dSFT):   ~2 hours
Stage 2 (AIF):    ~6 hours (API calls, single machine)
Stage 3 (dDPO):   ~2-4 hours
──────────────────────────────────────
Total:            ~10-12 hours (wall clock)
Cost:             ~$100-200 in compute + ~$2,000 in API calls

The use of DeepSpeed ZeRO-3 shards model parameters, optimizer states, and gradients across all 16 GPUs, enabling the 7B model to train with very large batch sizes. FlashAttention-2 reduces memory usage for attention computation by 5-20×, allowing longer sequences and larger batches. Together, these optimizations make the entire pipeline accessible to teams with modest GPU resources.

Comparison with Existing Methods

1

vs. Llama2-Chat (RLHF)

Zephyr surpasses Llama2-Chat-70B on MT-Bench with 10× fewer parameters, using AI-only data vs. human annotation. This connects to [Paper 08] (LIMA), which shows that data quality matters more than scale.

2

vs. Mistral-Instruct (DPO)

Zephyr surpasses the officially DPO-tuned Mistral variant, demonstrating that the dSFT + dDPO pipeline with AI feedback is more effective than standard DPO with human preferences.

3

vs. Guanaco (QLoRA)

Both use QLoRA ([Paper 07]) for efficient training, but Zephyr adds the DPO stage for preference alignment, resulting in better conversational quality.

Limitations

⚠️
  • AI feedback ceiling: The model is trained on GPT-4 preferences, which may introduce GPT-4's biases and limitations. The model cannot exceed GPT-4's judgment quality.
  • No human evaluation: All evaluation uses MT-Bench (GPT-4 scoring) and AlpacaEval (GPT-4 comparison). Human evaluation would provide a more reliable quality signal.
  • Single base model: The pipeline is only tested with Mistral-7B. Generalization to other base models (LLaMA, Phi, etc.) is not demonstrated.
  • API dependency: The AIF stage requires 256K GPT-4 API calls (~$2,000), which may be prohibitive for some teams. This connects to the cost analysis in [Paper 07] (QLoRA) about democratizing fine-tuning.
  • No safety evaluation: The paper doesn't include safety benchmarks or red-teaming. The model's behavior on harmful prompts is unknown.

Practical Implications

Zephyr established the SFT → DPO pipeline as the standard open-source alignment recipe. The key practical takeaways:

  • SFT is prerequisite for DPO: This is the paper's most important practical finding. Never apply DPO directly to a base model — always do SFT first. This finding has been validated by the broader community and is now standard practice.
  • AI feedback works: The fully automated pipeline (no human annotation) produces competitive results. This democratizes alignment — teams without access to human annotators can still train well-aligned models.
  • 1 epoch SFT, 3 epochs DPO: This training schedule is a good default for the SFT → DPO pipeline. More SFT epochs hurt; more DPO epochs don't help.
  • Quality filtering matters: The 7:1 filtering of UltraChat (1.47M → 200K) is critical. Applying DPO to unfiltered data degrades performance.
  • ORPO ([Paper 12]) builds on this: ORPO simplifies the Zephyr pipeline by merging SFT and DPO into a single stage, eliminating the need for a separate SFT phase and reference model.
