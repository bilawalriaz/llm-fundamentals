Self-Instruct: Aligning Language Models with Self-Generated Instructions

Yizhong Wang, Yeganeh Kordi, Swaroop Mishra, Alisa Liu, Noah A. Smith, Daniel Khashabi, Hannaneh Hajishirzi
arXiv 2212.10560
December 2022
Paper

Self-Instruct demonstrates that a language model can bootstrap a large corpus of instruction-following training data starting from just 175 human-written seed tasks. By iteratively generating new instructions, classifying them, producing input-output instances, and filtering out low-quality samples, the method produces 52,445 instructions and 82,439 instances — enough to fine-tune a vanilla GPT-3 model (DaVinci) to nearly match the performance of InstructGPT-001 on the SUPER-NATURAL INSTRUCTIONS benchmark. The core pipeline — seed → generate → filter → augment — became the foundational template for virtually all subsequent open-source instruction-tuning datasets, including Alpaca, WizardLM, and Vicuna.

1. The Problem: Instruction Data Is Expensive

Large language models like GPT-3 are powerful but largely unaligned to follow natural-language instructions. The dominant approach to alignment — reinforcement learning from human feedback (RLHF), as used in InstructGPT and ChatGPT — requires collecting large volumes of human-written instruction-input-output triples, which is slow, expensive, and hard to scale. Self-Instruct asks a deceptively simple question: can a language model generate its own instruction-tuning data?

The answer, demonstrated empirically, is yes — with careful engineering of a bootstrapping pipeline. The key insight is that while a model may not be perfectly instruction-aligned out of the box, it is already good enough to generate plausible instructions, and filtering heuristics can remove the garbage. This creates a flywheel: more generated data leads to better fine-tuned models, which in turn generate better data.

Key Insight: You don't need human-curated datasets at scale. A small set of seed tasks (175 examples) combined with a capable base model and smart filtering can bootstrap an entire instruction-tuning pipeline. This insight launched the synthetic instruction data paradigm.

2. Seed Task Design: The Foundation

The entire pipeline begins with a curated set of 175 seed tasks, each consisting of an instruction, an optional input, and an output. The authors carefully designed this pool to ensure diversity along two axes:

Category Count Description Examples
Classification tasks 25 Tasks with a fixed, closed set of labels Sentiment analysis, topic classification, language identification, hate speech detection, toxicity classification
Non-classification tasks 150 Open-ended generation, extraction, rewriting, summarization, and other generative tasks Writing a song, explaining a concept, translating text, generating code, answering questions, creating lists

The 15:1 ratio of non-classification to classification tasks reflects the real-world distribution of instruction-following needs — most user queries are open-ended, but classification tasks are important to include because they require structured outputs with fixed label spaces. Including classification tasks from the start prevents the model from generating only free-form text, which is a common failure mode.

"The 175 seed tasks are drawn from 18 different NLP datasets, ensuring broad coverage of task types while remaining small enough to be manually curated in a few hours."

3. The Full Generation Pipeline

The Self-Instruct pipeline is an iterative loop that expands the seed set into a massive corpus. Each iteration involves four distinct stages: instruction generation, classification branching, instance generation, and quality filtering.

3.1 Instruction Generation (Few-Shot Prompting)

To generate new instructions, the system samples a batch of existing tasks (typically 8–16) from the seed pool and presents them as few-shot examples to the base language model (GPT-3 DaVinci). Crucially, the sampled examples include a mix of human-written and model-generated instructions — this hybrid approach prevents the model from converging too quickly on a narrow style.

The prompt structure follows a straightforward pattern: a task description header, followed by several input-output examples, then a "New task:" prompt where the model generates the instruction. The model is instructed to produce a novel, diverse instruction that is distinct from the provided examples.

3.2 Classification Branching

After generating a new instruction, the system must decide whether it is a classification task (closed-label) or a non-classification task (open-ended). This branching is critical because the instance generation process differs significantly between the two:

  • Classification path: The model first generates a set of candidate labels (e.g., "positive," "negative," "neutral"), then generates inputs that correspond to each label. This ensures balanced coverage of the label space.
  • Non-classification path: The model generates input-output pairs directly, with the input preceding the output.

3.3 Input-First vs. Output-First Generation

The two generation strategies are designed to handle different instruction types optimally:

1

Input-First

The model generates an input first, then produces the corresponding output. Used for most non-classification tasks where the input defines the task scope (e.g., "Write a poem about spring" → input: "a poem about renewal and hope").

2

Output-First

The model generates the output first, then creates a plausible input that would produce it. Used when the output is the defining feature (e.g., classification labels, or tasks where the desired format is paramount).

3.4 ROUGE-L Filtering

Not all generated instructions are useful. The filtering stage applies two key heuristics:

Filter Threshold Purpose
ROUGE-L with seed tasks (upper) > 0.7 Remove instructions too similar to existing seeds (duplicates/near-duplicates)
ROUGE-L with seed tasks (lower) < 0.7 Retain instructions that are sufficiently novel
Length filter Input + output ≥ 3 tokens Remove degenerate empty or trivial instances
Repetition filter — Remove instructions with excessive word repetition
Keyword filter — Remove instructions referencing non-textual modalities (e.g., "image," "photo," "video")

The ROUGE-L threshold of 0.7 is a deliberate design choice. Instructions that are too similar to existing seeds (ROUGE-L > 0.7) are likely duplicates and add no diversity. Instructions that are too dissimilar (ROUGE-L < 0.7 from all existing instructions) might be malformed or incoherent. The sweet spot ensures genuine novelty while maintaining quality.

Why the "image" keyword filter matters: LLMs frequently generate instructions that reference images, photographs, or visual content — modalities they cannot process. Filtering these keywords prevents the dataset from containing unsolvable tasks.

3.5 The Round-Robin Loop

After filtering, the surviving instructions and their instances are added back into the seed pool. The next iteration samples from this expanded pool, including both original human-written seeds and model-generated tasks. This iterative process repeats for multiple rounds, with the quality and diversity of generated tasks improving as the seed pool grows. The round-robin approach ensures that no single generation dominates and that the model is continually exposed to a mix of human and synthetic instructions.

4. Dataset Statistics

The final Self-Instruct dataset is substantially larger than the seed set, demonstrating the power of the bootstrapping approach. The key statistics are summarized below:

Metric Value
Total instructions generated 52,445
Classification instructions 11,584 (22.1%)
Non-classification instructions 40,861 (77.9%)
Total instances (input-output pairs) 82,439
Average instruction length ~27 tokens
Average input length ~30 tokens
Average output length ~28 tokens
Seed tasks used 175

The 22.1% classification share is notable — it closely mirrors the authors' intentional effort to prevent mode collapse toward only open-ended tasks. Without the classification branching mechanism, the model would generate almost exclusively free-form text tasks.

5. Quality Analysis: How Good Is Synthetic Data?

To assess the quality of the generated dataset, the authors conducted a manual review of 200 randomly sampled instructions with their associated instances. The results paint a nuanced picture:

Quality Criterion Pass Rate Interpretation
Valid instruction 92% Nearly all generated instructions are coherent, well-formed natural language commands
Appropriate input 79% Most inputs match the instruction's intent and are plausible
Correct output 58% A little over half of the outputs correctly fulfill the instruction
All fields valid (instruction + input + output) 54% Only about half of all instances are fully correct end-to-end
The 54% figure is misleading in isolation. Even imperfect instances provide signal during fine-tuning — a model trained on 82K partially-correct examples still learns the format, style, and general capabilities of instruction following. The sheer volume compensates for individual instance noise. This is analogous to how noisy web-crawled data works for pre-training.

The gap between "valid instruction" (92%) and "correct output" (58%) reveals that the generation pipeline is much better at producing plausible prompts than at solving them. This makes sense: the model's instruction-following ability is the bottleneck, not its ability to generate task descriptions.

6. Diversity Analysis

A key concern with synthetic data generation is mode collapse — the model repeatedly generating the same types of tasks. The authors analyzed diversity along two axes:

Root Verb Distribution

The most common root verbs in generated instructions include: write, give, find, create, generate, explain, list, describe, identify, classify, and convert. The distribution is broad and relatively flat, indicating that the model generates a wide range of task types rather than converging on a few popular verbs.

ROUGE-L Overlap with Seeds

The generated instructions have low ROUGE-L overlap with the original seed tasks, confirming genuine novelty. The ROUGE-L filtering step is critical here — without it, the overlap would be significantly higher, as the model tends to reproduce patterns from the few-shot examples. By filtering at the 0.7 threshold, the pipeline ensures that the expanded dataset is genuinely diverse.

"The diversity of generated instructions is essential — a dataset of 50,000 near-duplicate instructions would be far less useful than 50,000 genuinely distinct tasks, even if the latter have lower per-instance quality."

7. Scaling Properties

One of the most practically important findings is how performance scales with dataset size. The authors evaluated models fine-tuned on increasing amounts of Self-Instruct data and found:

Dataset Size (instructions) SUPER-NI Score Trend
0 (vanilla GPT-3) Baseline —
~1,000 Significant improvement Steep initial gain
~8,000 Strong improvement Continued scaling
~16,000 Near-peak performance Diminishing returns begin
~52,000 Peak performance Plateau — additional data yields marginal gains

Performance plateaus at approximately 16,000 instructions, after which additional data provides only marginal improvements. This has significant practical implications: researchers can achieve near-optimal results with a fraction of the full dataset, reducing fine-tuning costs. The plateau likely reflects the model's capacity to learn instruction-following from a representative sample — beyond a point, more data merely replicates the same task types.

8. Distillation: Borrowing From Stronger Models

Self-Instruct also explores the effect of using a stronger model to generate the output instances. Instead of having GPT-3 DaVinci generate both instructions and their corresponding outputs, the pipeline can use InstructGPT-003 (the model behind early ChatGPT) to regenerate the outputs while keeping the self-generated instructions.

This "distillation" approach yields a +10% improvement in SUPER-NI performance. The gains come from higher-quality outputs — InstructGPT-003 produces more accurate, well-formatted responses than the base DaVinci model, while the self-generated instructions retain their diversity and novelty.

The distillation result is a key nuance: The quality of instructions matters less than the quality of the input-output pairs they produce. Self-generated instructions can be noisy, but if the outputs are generated by a strong model, the resulting dataset is highly effective. This suggests the instruction diversity is more important than instruction perfection.

9. Benchmark Results: Nearly Matching InstructGPT

The headline result of Self-Instruct is that a fine-tuned DaVinci model, trained exclusively on self-generated data, nearly matches the performance of InstructGPT-001 on the SUPER-NATURAL INSTRUCTIONS benchmark — achieving 39.9 versus InstructGPT-001's 40.8.

Model SUPER-NI Score Training Data
Vanilla GPT-3 (DaVinci) Baseline (no fine-tuning) None (zero-shot/few-shot)
Self-Instruct (DaVinci, fine-tuned) ~33% improvement over baseline 52K self-generated instructions
InstructGPT-001 40.8 Human-curated instruction data + RLHF
Self-Instruct (DaVinci, distilled) ~39.9 Self-generated instructions + InstructGPT-003 outputs

The +33% improvement over the vanilla baseline demonstrates that even without human feedback, instruction tuning with synthetic data provides substantial alignment gains. The near-parity with InstructGPT-001 is remarkable given that InstructGPT-001 was trained on carefully curated human data with reinforcement learning.

10. Human Evaluation: 252 Novel Tasks

Beyond automated benchmarks, the authors conducted a thorough human evaluation on 252 novel tasks — tasks not present in the training data or seed set. Human evaluators compared outputs from the Self-Instruct model against InstructGPT-001 across multiple criteria:

  • Instruction understanding: Did the model correctly interpret the task?
  • Output quality: Was the response helpful, accurate, and well-formatted?
  • Factual correctness: Were the claims in the output accurate?

The Self-Instruct model achieved only a 5% performance gap relative to InstructGPT-001 on human evaluation. This is a striking result: it means that a model trained purely on self-generated data — no human annotations, no reinforcement learning — performs nearly as well as a model trained with expensive human feedback pipelines.

"A 5% gap to InstructGPT-001 on human evaluation — using only self-generated data — demonstrates that the quality ceiling of synthetic instruction data is remarkably high."

11. Limitations and Open Challenges

Despite its impressive results, Self-Instruct has several acknowledged limitations:

Tail Phenomena

The model struggles with rare, specialized, or "long-tail" tasks that are underrepresented in the training data. The bootstrapping process naturally favors common task types — instructions that are easy to generate and validate. Tasks requiring deep domain expertise, multi-step reasoning, or niche knowledge are poorly served.

Large Model Dependence

The entire pipeline depends on having a sufficiently capable base model. GPT-3 DaVinci (175B parameters) was used as both the generator and the fine-tuning target. Smaller models may not generate high-quality instructions, creating a chicken-and-egg problem: you need a large model to generate the data to train a smaller model, but the smaller model's generation quality may be too poor to bootstrap.

Bias Amplification

Since the base model's biases are baked into the generated data, Self-Instruct can amplify existing biases in the training corpus. The model may generate instructions and outputs that reflect stereotypes, cultural biases, or factual errors present in its pre-training data. Without human review, these biases propagate unchecked through the pipeline.

Output Quality Ceiling

As noted in the quality analysis, only 58% of generated outputs are correct. This means nearly half the training data contains errors. While volume compensates to some extent, the quality ceiling limits the maximum performance achievable through self-instruction alone.

12. The Superficial Alignment Hypothesis

Self-Instruct's results are deeply connected to the superficial alignment hypothesis, which argues that alignment fine-tuning primarily teaches a model the format and style of helpful responses rather than fundamentally changing its knowledge or reasoning capabilities. The fact that self-generated data works so well supports this view: the model already "knows" how to perform many tasks — it just needs to learn the conversational format of responding to instructions.

See Paper 08 (LIMA) for the superficial alignment hypothesis, which formalizes this observation: with the right fine-tuning data, even a small number of carefully curated examples (as few as 1,000 in LIMA's case) can achieve remarkable alignment. Self-Instruct demonstrates the complementary result: quantity of synthetic data can achieve similar alignment effects through a different route.

Cross-reference: See Paper 08 (LIMA) for the superficial alignment hypothesis. LIMA argues that alignment is "superficial" — models already possess the knowledge; fine-tuning merely teaches the format. Self-Instruct provides strong empirical support: self-generated data, which is noisy and imperfect, still achieves near-InstructGPT performance because the base model already has the underlying capabilities.

13. Impact and Legacy

Self-Instruct's impact on the field cannot be overstated. The paper introduced the synthetic instruction data paradigm that became the foundation for virtually every open-source instruction-tuned model:

Downstream System Relationship to Self-Instruct
Stanford Alpaca Directly adapted the Self-Instruct pipeline with text-davinci-003 as the generator
WizardLM Extended the pipeline with evolutionary instruction prompting for more complex tasks
Vicuna Used self-instruct-style data alongside conversation data from ShareGPT
Orca / Orca 2 Adapted the pipeline with "explanation tuning" — adding reasoning traces to outputs
Koala, Pythia, and others Various adaptations of the seed → generate → filter → train loop

The core loop — seed → generate → filter → augment → retrain — is now standard practice for anyone creating custom SFT (supervised fine-tuning) datasets. Self-Instruct proved that you don't need expensive human annotation to align a model; you just need a good base model and a well-designed pipeline.

14. Summary of Contributions

Seed Task Bootstrapping 52K Instructions 82K Instances ROUGE-L Filtering Classification Branching +33% SUPER-NI Near InstructGPT-001 +10% Distillation Gain 5% Human Eval Gap Synthetic Data Paradigm

Self-Instruct is a landmark paper that demonstrated the viability of self-generated instruction data for alignment. Its contributions are threefold: (1) a practical, reproducible pipeline for generating instruction-tuning data from minimal human effort; (2) rigorous empirical analysis of data quality, diversity, and scaling properties; and (3) benchmark results showing near-parity with human-curated approaches. The paper's legacy is visible in every open-source instruction-tuned model released since its publication.

"Self-Instruct showed that the gap between proprietary and open-source alignment could be closed — not by better RLHF, but by cleverer data generation."
