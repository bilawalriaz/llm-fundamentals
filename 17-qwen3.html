Qwen3 is Alibaba's most comprehensive open model family, spanning 7 dense models (0.6B–35B) and 2 MoE models (30B-A3B and 235B-A22B), pretrained on 36 trillion tokens across 119 languages. Its defining innovation is a 4-stage post-training pipeline that produces models capable of both explicit chain-of-thought reasoning (thinking mode) and direct response generation (non-thinking mode), switchable at inference time. The pipeline combines Long-CoT cold start, GRPO-based reasoning RL, thinking mode fusion, and general RL—representing the most sophisticated alignment recipe publicly documented. A strong-to-weak distillation approach enables small models (4B, 8B) to inherit reasoning capabilities from the 235B model at ~10× efficiency.

1. Research Overview and Context

Qwen3 represents the state of the art in open-weight model alignment as of May 2025. While previous model families focused on either pretraining scale or single-stage alignment, Qwen3 introduces a multi-stage post-training pipeline that systematically builds capabilities from cold-start reasoning through general alignment. The paper's central innovation—thinking/non-thinking mode switching—allows a single model to serve both latency-sensitive applications (direct responses) and complex reasoning tasks (explicit thought chains), controlled by a simple chat template mechanism.

The paper also introduces a practical approach to model distillation: larger models generate reasoning traces that are distilled into smaller models, enabling 4B and 8B models to achieve reasoning capabilities that would otherwise require 100B+ parameter scales. This strong-to-weak distillation approach is approximately 10× more efficient than training the reasoning capability from scratch in smaller models.

🎯
Key Contributions: (1) 4-stage post-training pipeline: Long-CoT cold start → Reasoning RL (GRPO) → Thinking mode fusion → General RL. (2) Thinking/non-thinking mode switching controlled via system prompts. (3) Strong-to-weak distillation enabling small models with reasoning capabilities. (4) 36T token pretraining across 119 languages—the most multilingual open model family. (5) Comprehensive evaluation showing competitive performance with proprietary models.

3. 36T Token Pretraining Across 119 Languages

Qwen3's pretraining corpus is the largest and most multilingual open training dataset to date: 36 trillion tokens across 119 languages. The pretraining uses a 3-stage curriculum that progressively increases data quality and complexity:

3.1 Three-Stage Pretraining Curriculum

1

Stage 1: Long-Context Pretraining

Train on long-context data to establish long-range dependency handling. Uses position-aware data mixing with emphasis on documents requiring context across thousands of tokens.

2

Stage 2: STEM and Code Focus

Emphasize STEM and code data (~5T tokens) to build strong reasoning capabilities. This follows the code→math transfer insight from Paper 14.

3

Stage 3: Quality-Curated Final

Final pretraining stage with curated high-quality data. Teacher-model generated synthetic data for complex reasoning tasks. Polish and refine all capabilities.

3.2 Long-Context Techniques

Qwen3 achieves its 32K base context through a combination of techniques:

  • ABF (Adjusted Base Frequency): Modifies the base frequency of rotary position embeddings to extend the effective context window. This is a simpler alternative to LongRope (see Paper 16) but effective for moderate extensions.
  • YARN (Yet Another RoPE Extension): Applies scaled RoPE with interpolation to extend context length. Uses a combination of attention scaling and position interpolation.
  • Dual Chunk Attention: Splits the attention computation into local and global chunks, reducing memory for long sequences while maintaining quality.
  • Progressive context increase: The 3-stage pretraining progressively increases context length, allowing the model to gradually adapt to longer sequences.

"36 trillion tokens across 119 languages makes Qwen3 the most multilingual open model family ever pretrained. The 3-stage curriculum ensures the model builds both broad language coverage and deep reasoning capabilities."

4. The 4-Stage Post-Training Pipeline

Qwen3's most significant contribution is its 4-stage post-training pipeline, which is the most sophisticated alignment recipe publicly documented. Each stage builds on the previous one, systematically developing specific capabilities:

Stage 1: Long-CoT Cold Start

The first stage initializes the model's reasoning capability by fine-tuning on long chain-of-thought (CoT) data. This data consists of detailed reasoning traces generated by larger models (or human annotators), where each step of the reasoning process is explicitly written out.

Stage 2: Reasoning RL (GRPO)

The second stage applies Group Relative Policy Optimization (GRPO) to improve reasoning capabilities through reinforcement learning. This follows the approach from Paper 14, but extended to handle Qwen3's broader task distribution.

    1. Sample G outputs: {y_1, ..., y_G} ~ π_θ(·|x)
    2. Compute rewards: {r_1, ..., r_G} using verifiable rewards
    3. Compute group-relative advantages:

Why GRPO over PPO: As established in Paper 14, GRPO eliminates the learned value function from PPO, reducing memory by ~50% while maintaining performance. For a 235B MoE model, this saving is critical—eliminating the critic network saves ~235B parameters worth of memory. See Paper 14 Section 4 for the complete GRPO derivation.

Stage 3: Thinking Mode Fusion

The third stage is the most innovative: it trains the model to switch between thinking and non-thinking modes. This is achieved through a thought-free SFT stage that teaches the model to produce direct responses when thinking is not required, while retaining the ability to generate explicit reasoning chains when thinking is activated.

THINKING MODE (explicit reasoning):
  Input:  " /think What is 234 × 567?"
  Output: "\nLet me compute this step by step.\n234 × 567\n= 234 × 500 + 234 × 67\n= 117000 + 15678\n= 132678\n\nThe answer is 132,678."

  Input:  " /no_think What is 234 × 567?"
  Output: "234 × 567 = 132,678"

Training data:
  - Mixed examples with ... tags and without
  - System prompt controls: "/think" enables thinking, "/no_think" disables it
  - The model learns to respect these control signals

Key design:
  - No separate models needed—one model, two modes
  - Mode switching controlled via chat template / system prompt
  - Thinking budget: max tokens for  section can be set

Stage 4: General RL

The final stage applies GRPO to general tasks—creative writing, instruction following, safety, and helpfulness—using both verifiable and model-judged rewards. This stage improves the model's broad capabilities without degrading the reasoning capabilities developed in stages 1-3.

The general RL stage is particularly important because it addresses tasks where rewards are not easily verifiable (e.g., "is this creative writing good?"). Qwen3 uses a combination of rule-based rewards (for structured tasks) and LLM-judge rewards (for subjective tasks) to train across the full spectrum of capabilities.

"The 4-stage pipeline is the most sophisticated alignment recipe publicly documented. Each stage builds on the previous one: cold start teaches reasoning expression, GRPO improves reasoning quality, thinking mode fusion adds flexibility, and general RL polishes broad capabilities."

6. Strong-to-Weak Distillation

One of Qwen3's most practical contributions is its strong-to-weak distillation approach, which enables small models (4B, 8B) to inherit reasoning capabilities from the 235B flagship model. This approach is approximately 10× more efficient than training the reasoning capability from scratch in smaller models.

6.1 Two-Phase Distillation

The distillation process has two phases: off-policy distillation and on-policy distillation: 

Strong-to-Weak Distillation Pipeline:
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Phase 1: Off-Policy Distillation
  Source: Qwen3-235B-A22B (teacher) in thinking mode
  Target: Qwen3-4B / Qwen3-8B (student)
  
  Process:
    1. Teacher generates long reasoning traces for training prompts
    2. Student is trained via SFT on these traces
    3. The student learns to mimic the teacher's reasoning pattern
  
  Data: ~100K-500K teacher-generated reasoning traces
  Training: Standard SFT loss on (prompt, reasoning_trace) pairs

Phase 2: On-Policy Distillation
  Source: Qwen3-235B-A22B (teacher) with online sampling
  Target: Qwen3-4B / Qwen3-8B (student)
  
  Process:
    1. Student generates its own responses
    2. Teacher evaluates and corrects student outputs
    3. Student trains on corrected outputs
  
  Advantage: Student learns from its own failure modes
  Training: Mixed SFT + preference optimization

Efficiency: ~10× more efficient than training reasoning from scratch
  - Small models don't need the expensive RL stage (Stage 2)
  - They inherit reasoning through distillation instead
  - This saves ~10× the compute of training GRPO from scratch
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

6.2 Why Distillation Replaces RL for Small Models

The key insight is that small models (4B, 8B) lack the capacity to discover reasoning strategies through exploration (RL). The GRPO stage in the 235B model benefits from the model's ability to explore diverse reasoning paths—a luxury that small models cannot afford because their exploration is limited by their capacity. Distillation bypasses this limitation by directly providing the reasoning traces from the larger model.

💡
Distillation Economics: Training the GRPO stage for the 235B model requires massive compute (likely thousands of GPU-hours on A100s/H100s). Generating reasoning traces and training a 4B student requires approximately 100× less compute. For teams without access to large GPU clusters, distillation provides a practical path to capable reasoning models.

7. GRPO: Group Relative Policy Optimization

GRPO is the core RL algorithm used in Qwen3's post-training pipeline. As established in Paper 14, GRPO eliminates the learned value function from PPO, replacing it with group-relative advantage estimation. This section focuses on Qwen3's specific application and extensions:

7.1 Reward Design Across Stages

Stage Reward Type Examples RL Algorithm
Stage 2: Reasoning RL Verifiable rewards Math correctness, code pass@1, logic validity GRPO
Stage 4: General RL Mixed rewards Rule-based + LLM-judge GRPO

7.2 GRPO vs. DPO for Reasoning Tasks

Qwen3 uses GRPO instead of DPO for the reasoning RL stage. The advantages are:

  • Online exploration: GRPO generates new samples each training step, discovering reasoning strategies not present in the training data. DPO is offline and limited to the preference dataset.
  • No reference model needed: GRPO eliminates the reference model dependency of DPO, reducing memory by ~50%.
  • Verifiable rewards: For math/code/logic, rewards are objective and verifiable. GRPO leverages this directly, while DPO requires preference labels.
  • Continuous improvement: GRPO's online nature means the model continuously improves during training, while DPO's offline nature limits improvement to what's in the dataset.

However, DPO remains relevant for tasks without verifiable rewards (creative writing, general instruction following). Qwen3's approach—GRPO for verifiable tasks, DPO/similar for subjective tasks—represents the current best practice. See Paper 10 for DPO theory and Paper 13 for SFT+DPO interaction.

9. Long-Context Architecture and Evaluation

Qwen3 supports 32K context natively, with extended context capabilities through several techniques:

9.1 ABF (Adjusted Base Frequency)

ABF modifies the base frequency of RoPE to extend the effective context window. For a model trained with base frequency b_0, ABF scales it to b_0 × α where α is a scaling factor computed from the target context length. This is simpler than LongRope (see Paper 16) but effective for moderate extensions.

9.2 YARN (Yet Another RoPE Extension)

YARN combines RoPE interpolation with attention scaling to extend context length. The approach: 

YARN Context Extension:
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Standard RoPE: θ_i = 1 / (base^(2i/d))

YARN modification:
  1. Position interpolation: pos' = pos × (L_train / L_target)
  2. Attention scaling: scale = L_target / L_train
  3. Frequency band weighting:
     - Low frequencies: full interpolation (local patterns)
     - High frequencies: partial interpolation (long-range)
     - Transition band: smooth blending

Result: Extends context from 32K to 128K+ with minimal
        quality degradation on long-context benchmarks.
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

9.3 Dual Chunk Attention

Dual Chunk Attention splits the attention computation into two parts: local attention (within a chunk of nearby tokens) and global attention (across chunks). This reduces memory from O(n²) to O(n × chunk_size) while maintaining the ability to attend to distant tokens through the global component.

10.1 Inference Optimization

Qwen3 supports several inference optimizations:

  • GQA (Grouped Query Attention): Reduces KV-cache memory for efficient long-context inference
  • MoE quantization: INT4/INT8 quantization for the MoE models, reducing memory from ~470GB (FP16) to ~120GB (INT4) for the 235B model
  • Continuous batching: vLLM and TensorRT-LLM support for high-throughput serving
  • Speculative decoding: Uses a small model to draft tokens, verified by the large model

11. Limitations

⚠️
Key Limitations:

Compute requirements. The 4-stage post-training pipeline is computationally expensive. Training the GRPO stage for the 235B model likely requires thousands of GPU-hours on H100s. This limits reproducibility for most research groups.

Distillation quality ceiling. While strong-to-weak distillation is efficient, it introduces a quality ceiling: the student can never exceed the teacher's capability. The distilled 4B model inherits the teacher's reasoning patterns but cannot discover novel strategies.

Mode switching reliability. The thinking/non-thinking mode switching is controlled by system prompts, which can be overridden by user inputs. Adversarial users may force thinking mode in latency-sensitive deployments or disable it in reasoning-critical applications.

Verifiable reward limitation. GRPO requires verifiable rewards for reasoning tasks. For open-ended tasks (creative writing, subjective analysis), the reward design is less straightforward and relies on LLM judges, which introduce their own biases.

Multilingual evaluation gaps. While pretrained on 119 languages, the evaluation focuses primarily on English, Chinese, and a few major languages. Performance on low-resource languages may degrade significantly.

12. Practical Implications

12.1 For Alignment Pipelines

Adopt the 4-stage pipeline. The Long-CoT cold start → Reasoning RL → Thinking fusion → General RL pipeline is the current best practice for building models with both reasoning and general capabilities. Each stage is essential and builds on the previous one.

Use GRPO for verifiable tasks. For math, code, and logic, GRPO (from Paper 14) is more effective than DPO (from Paper 10). Reserve DPO for tasks without verifiable rewards.

Invest in distillation. For teams without massive compute budgets, strong-to-weak distillation from a large model provides a practical path to capable small models. The 10× efficiency advantage is substantial.

12.2 For Deployment

Offer both modes. Thinking mode for complex tasks, non-thinking mode for simple tasks. This dual-mode capability is a significant UX advantage over single-mode models.

Set thinking budgets. For production deployments, set explicit thinking token budgets to prevent runaway reasoning chains from consuming excessive compute.
