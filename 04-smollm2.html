SmolLM2: When Smol Goes Big

Ben Allal, Anton Lozhkov, Quentin Gallouédec, & HuggingFace Team
arXiv:2502.02737
February 2025
arXiv Paper

SmolLM2 is a family of small language models (135M, 360M, 1.7B parameters) from HuggingFace that achieves state-of-the-art performance at small scale through meticulous data curation and multi-stage training. The paper introduces three new datasets (FineMath, Stack-Edu, SmolTalk), details a 4-stage pretraining curriculum with online data rebalancing, extends context from 2K to 8K tokens, and demonstrates that SFT + DPO post-training works effectively at small scale. SmolLM2-1.7B beats models up to 3× its size, providing the most comprehensive open study of small-model training methodology.

1. Motivation: Small Models for Everyone

While large language models dominate headlines and benchmarks, the practical reality is that most deployment scenarios require models that can run on consumer hardware, edge devices, or cost-constrained servers. A 70B model requires multiple A100 GPUs; a 1.7B model can run on a single laptop GPU. SmolLM2's goal is to push the performance frontier of small models as far as possible, making capable AI accessible to developers without massive compute budgets.

Following the principle established in Paper 03: Phi-1 — that data quality trumps model scale — SmolLM2 applies systematic data curation at every stage of training. But where Phi-1 focused on a single domain (Python code), SmolLM2 tackles general-purpose language modeling, requiring careful balancing of web text, code, mathematics, and educational content.

"For small models, dataset quality and composition matter more than architecture or training tricks. The recipe is the data."

2. Three New Curated Datasets

2.1 FineMath: Mathematical Reasoning Data

Mathematical reasoning is a critical capability that small models typically lack. FineMath is a filtered subset of web-crawled mathematical content, created through a multi-stage pipeline:

1

Source Extraction

Mathematical content is extracted from CommonCrawl using URL patterns (math forums, educational sites, Wikipedia math articles) and content analysis (LaTeX detection, equation presence).

2

Quality Filtering

A classifier scores each page for mathematical content quality. Pages with well-explained solutions, step-by-step derivations, and clear formatting score highest.

3

Deduplication

Exact and fuzzy deduplication removes redundant content. Common mathematical identities and formulas that appear thousands of times are kept only once.

4

Educational Value Scoring

Similar to Phi-1's textbook-quality concept, an LLM-based classifier identifies content that teaches rather than merely references mathematics.

5

Final Filtering

Content below quality thresholds is removed. The final FineMath dataset contains high-quality mathematical explanations, worked examples, and proofs.

2.2 Stack-Edu: Educational Code Data

Building on the Phi-1 insight that educational code is more valuable than raw code, Stack-Edu applies pedagogical quality scoring to The Stack (a large code dataset). The key innovation is an educational value scoring system that evaluates code files for:

CriterionWeightMeasurement
Comment densityHighRatio of comment lines to code lines
Function docstringsHighPresence and quality of docstrings
Variable namingMediumDescriptiveness of identifiers
Code complexityMediumCyclomatic complexity (lower = more educational)
README qualityMediumDocumentation completeness
Dependency countLowFewer dependencies = more self-contained

The scoring uses a combination of heuristic rules and LLM-based classification, similar to Phi-1's approach but applied at scale to the entire Stack dataset. Stack-Edu retains approximately 15-20% of The Stack by educational quality.

2.3 SmolTalk: Synthetic Instruction-Following Data

SmolTalk is a synthetic dataset of instruction-following conversations designed for supervised fine-tuning (SFT). Unlike general-purpose instruction datasets (OpenAssistant, Dolly), SmolTalk is specifically designed for small models:

  • Complexity-matched: Conversations are generated at a complexity level appropriate for small models — clear, direct, well-structured
  • Diverse task types: Covers question-answering, summarization, code generation, math reasoning, creative writing, and conversation
  • Multi-turn format: Includes both single-turn and multi-turn conversations to teach dialogue management
  • Quality filtering: Generated conversations are filtered for coherence, helpfulness, and safety

3.2 Grouped-Query Attention (GQA)

A key architectural choice is grouped-query attention (Ainslie et al., 2023), where multiple query heads share key-value heads. In the 1.7B model, 32 query heads share 8 KV heads (4:1 ratio). This reduces the KV cache during inference by 4×, meaning the model can serve longer sequences with the same memory budget. The attention mechanism itself is unchanged — see Paper 01: The Illustrated Transformer for the full attention formulation — but the key and value projections are shared across groups of query heads.

The mathematical formulation: in standard multi-head attention, each head i has its own W_K_i and W_V_i. In GQA, heads are grouped, and within each group, all heads share the same key and value projections: 

Standard MHA: head_i = Attn(Q·W_Q_i, K·W_K_i, V·W_V_i)  [all independent]
GQA:          head_i = Attn(Q·W_Q_i, K·W_K_{g(i)}, V·W_V_{g(i)})  [shared KV per group]

4. Four-Stage Pretraining

4.1 Stage Overview

SmolLM2 uses a curriculum-style training approach with four distinct stages, each with a different data mixture. The key innovation is online rebalancing — dynamically adjusting data mixtures during training based on model performance.

StageTokensFocusKey Data Sources
Stage 1: General~6TBroad web knowledgeWeb data, filtered CommonCrawl
Stage 2: Specialization~3TCode + Math emphasisStack-Edu, FineMath, code data
Stage 3: High-quality~1.5TEducational contentTextbook-quality data, Wikipedia
Stage 4: Annealing~0.5TFine-tuning readinessBalanced mix, LR decay

Total training: approximately 11 trillion tokens across all model sizes, with compute-optimal scaling per size (smaller models see more tokens relative to their parameter count).

4.2 Online Data Rebalancing

The most novel aspect of the training procedure is online rebalancing. Instead of fixing the data mixture at the start of training, SmolLM2 monitors validation loss on different data domains and adjusts the mixture ratio during training:

1

Monitor Loss

Track validation loss separately for each data domain (web, code, math, educational).

2

Identify Plateaus

When a domain's loss plateaus (stopped improving), reduce its sampling weight.

3

Boost Underperformers

Increase weight for domains where the model still shows significant improvement.

This is analogous to a teacher adjusting their curriculum based on student progress — spending more time on topics the student hasn't mastered yet. The rebalancing happens at regular intervals (every ~100M tokens) and prevents the model from overfitting to easy domains while neglecting harder ones.

🔄
Online vs. offline rebalancing: Traditional approaches fix the data mixture before training (e.g., 70% web, 15% code, 10% math, 5% educational). Online rebalancing is dynamic — the mixture evolves during training. This is more computationally expensive (requires validation evaluation) but produces better results because the data mix adapts to the model's current capabilities. This connects to the multi-stage approach in Paper 05: Flan Collection, which also varies task mixtures during training.

4.3 Learning Rate Schedule: WSD

SmolLM2 uses a Warmup-Stable-Decay (WSD) learning rate schedule: 

WSD Schedule:
  Warmup:  Linear increase from 0 to peak LR over ~2000 steps
  Stable:  Constant peak LR for most of training (~80% of steps)
  Decay:   Cosine decay from peak LR to near-zero over final ~20% of steps

Peak LR:  3e-4 (1.7B), 6e-4 (360M), 1e-3 (135M)
Min LR:   1e-5 (all sizes)

The WSD schedule differs from the traditional warmup-decay schedule (used in the original Transformer, see Paper 01) by including a long stable period at peak learning rate. This allows the model to explore the loss landscape more thoroughly before the final decay phase refines the solution. The decay phase is particularly important for the annealing stage, where the model fine-tunes on the highest-quality data.

5. Context Extension: 2K to 8K

The base model is initially trained with a context length of 2,048 tokens. To extend to 8,192 tokens, SmolLM2 uses a two-phase approach:

  • Phase 1 (continued pretraining): The model is further trained on longer sequences using RoPE (Rotary Position Embedding) frequency scaling. The RoPE frequencies are adjusted so that the model can handle 8K positions without catastrophic forgetting of short-range capabilities.
  • Phase 2 (finetuning): Long-context instruction data (multi-document summarization, long conversations) is used to teach the model to actually use the extended context.

The context extension is validated using the Needle-in-a-Haystack test, where the model must retrieve a specific fact placed at various positions within a long document. SmolLM2-1.7B achieves >95% accuracy across all positions in 8K-length sequences.

6. Post-Training Pipeline

6.1 Supervised Fine-Tuning (SFT)

After pretraining, the model is fine-tuned on SmolTalk using standard SFT. The SFT stage teaches the model to follow instructions, maintain conversation format, and be helpful. Key details:

ParameterValue
DatasetSmolTalk (~1M conversations)
Learning rate2e-5 (1.7B), 5e-5 (smaller)
Epochs2-3
Batch size128 sequences
Max sequence length8192 tokens
Loss maskingOnly on assistant turns

6.2 Direct Preference Optimization (DPO)

After SFT, DPO is applied for alignment using the UltraFeedback dataset. DPO trains the model to prefer helpful, harmless responses over less desirable ones, without requiring a separate reward model: 

DPO Loss:
  L_DPO = -E[log σ(β · (log π_θ(y_w|x) / π_ref(y_w|x) - log π_θ(y_l|x) / π_ref(y_l|x)))]

where:
  π_θ = policy model (being trained)
  π_ref = reference model (SFT checkpoint, frozen)
  y_w = preferred (chosen) response
  y_l = dispreferred (rejected) response
  β = temperature parameter (0.1)
  σ = sigmoid function

The reference model is the SFT checkpoint, held fixed during DPO training. This ensures the model doesn't drift too far from the SFT behavior while learning preference alignment.

9. Limitations

  • Benchmark gap with larger models: On knowledge-intensive tasks (MMLU), SmolLM2-1.7B still lags significantly behind 7B+ models. Small models have inherent capacity limits for factual knowledge.
  • Math limits: While FineMath improves mathematical reasoning, the 1.7B base model still struggles with multi-step mathematical problems. GSM8K performance (32.7%) is far below practical usability; the instruct model reaches about 49%.
  • Code complexity: HumanEval at 38.4% is respectable but insufficient for production code generation. Complex, multi-file coding tasks remain beyond reach.
  • Training compute: 11T tokens across three model sizes represents significant compute investment, even if individual models are small.
  • Evaluation limitations: Many benchmarks don't capture real-world utility. A model's value depends on specific use cases, not aggregate scores.

10. Practical Implications

SmolLM2 provides the most complete open-source recipe for training small language models:

  • Data curation is the primary lever: Three carefully curated datasets (FineMath, Stack-Edu, SmolTalk) are publicly available and widely reused.
  • Multi-stage training works: The 4-stage curriculum with online rebalancing is a practical, reproducible training recipe.
  • SFT + DPO at small scale: The post-training pipeline (SFT on SmolTalk + DPO on UltraFeedback) works effectively for models as small as 135M parameters.
  • Context extension is feasible: Extending from 2K to 8K context is achievable with continued pretraining and RoPE scaling, even for small models.
  • GQA for inference efficiency: Grouped-query attention provides meaningful speedups for serving small models in production.
🎯
Key takeaway: SmolLM2 demonstrates that the full pipeline — data curation → multi-stage pretraining → SFT → DPO — works at small scale. The 1.7B model beats competitors up to 3× its size by combining the data quality principle from Phi-1 with systematic training methodology. The publicly available datasets and training recipes make this the most practical reference for anyone training small language models.
