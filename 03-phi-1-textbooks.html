Textbooks Are All You Need

Gunasekar, Zhang, Anber, Menber, & Choudhary (Microsoft Research)
arXiv:2306.11644
June 2023
arXiv Paper

Phi-1 is a 1.3B parameter code-generation model that achieves 50.6% on HumanEval — a result previously thought to require models 10-100× larger. The paper's central thesis is that data quality trumps model scale. By carefully curating a training corpus of only 7B tokens filtered for "textbook quality" — well-commented, pedagogically structured, self-explanatory code — and supplementing with synthetic exercises generated by GPT-3.5, the authors demonstrate that a tiny model can match or exceed much larger competitors. This paper launched the "data-centric AI" movement and directly influenced subsequent work including SmolLM2 and Phi-2/3.

1. Motivation: The Data Quality Hypothesis

In mid-2023, the dominant paradigm in AI was scaling: make the model bigger, train on more data, and capabilities emerge. GPT-4, PaLM, and LLaMA-65B demonstrated that scale produces impressive results. But scale is expensive — training a 65B model requires thousands of GPUs and millions of dollars. Gunasekar et al. asked a provocative question: is scale actually necessary, or is the quality of training data the real bottleneck?

The hypothesis was inspired by human learning: a student doesn't learn programming by reading millions of lines of random code. They learn from carefully written textbooks, tutorials, and exercises that are designed to teach concepts progressively. What if we could curate training data that teaches rather than merely exposes? This connects to the findings in Paper 02: TinyStories, which showed that constrained, pedagogically structured data allows small models to learn effectively.

"If you give a student a well-written textbook and some exercises, they can learn far more effectively than if you give them a billion lines of randomly scraped code. The same principle applies to neural networks."

2. The CodeTextbook Filtering Pipeline

2.1 Source Data

The starting point is a large corpus of code from The Stack and GitHub, containing billions of tokens of Python code. Most of this code is typical open-source software: variable names like x and tmp, minimal comments, complex dependencies, and production-oriented patterns. This is not what a good textbook looks like.

2.2 The GPT-4 Classifier

The core innovation is a binary classifier powered by GPT-4 that scores each code file for "educational value." The classifier is prompted with examples of textbook-quality code vs. typical code, and asked to determine which category a given code file falls into.

1

Sample Code Files

Extract individual Python files/functions from the source corpus.

2

GPT-4 Classification

GPT-4 evaluates each file against a rubric for educational quality. The prompt includes few-shot examples of good and bad code.

3

Score & Threshold

Files scoring above the threshold are retained. The threshold is calibrated to keep approximately the top 5-10% of code by educational quality.

3. Synthetic Textbook Generation

3.1 Prompt Design

The filtered CodeTextbook provides high-quality code examples, but it lacks narrative structure — the explanatory text that connects code examples and teaches concepts. To address this, the authors use GPT-3.5-turbo to generate synthetic textbook content: prose explanations accompanied by code examples, organized into chapters covering specific programming concepts.

The generation prompts follow a structured template: 

Prompt template (simplified):
"Write a textbook chapter about {concept} for beginners.
 Include:
 - Clear explanation of the concept
 - Why it's important
 - Step-by-step code examples with comments
 - Common mistakes to avoid
 - Practice exercises with solutions

 Use simple Python without external dependencies.
 Write as if teaching a student who has never programmed before."

3.2 Randomness Injection

To prevent mode collapse and ensure diversity, the prompts include controlled randomness:

  • Concept rotation: Different programming concepts are targeted in each generation (loops, conditionals, data structures, functions, OOP, file I/O, etc.)
  • Style variation: Prompts specify different writing styles (tutorial, reference, problem-solution, narrative)
  • Difficulty levels: Some chapters target beginners, others intermediate learners
  • Domain variation: Code examples span different application domains (games, data processing, utilities, simulations)

3.3 CodeExercises: Synthetic Problem-Solution Pairs

The second synthetic data component is CodeExercises: programming exercises with solutions, generated by GPT-3.5. Each exercise includes:

  • A problem statement describing what the code should do
  • Expected input/output examples
  • A complete, well-commented solution
  • Alternative solutions where applicable

These exercises are critical because they teach problem-solving patterns — the ability to translate a natural language description into code. This is exactly what HumanEval tests: given a docstring, generate the corresponding function.

4. Training Data Composition

4.1 The 7B Token Corpus

The final training corpus is remarkably small — only 7B tokens. For comparison, typical code models are trained on 50B-500B tokens. The composition:

Scale comparison: 7B tokens is approximately 0.007% of what GPT-3 was trained on (300B tokens), and about 1% of what CodeLlama used (500B tokens). This paper demonstrates that carefully curated data at this scale can produce results competitive with models trained on 10-70× more data. This connects to Paper 02: TinyStories, which showed the same principle for children's stories.

5.2 FlashAttention and Parallel MLP/MHA

The model uses FlashAttention-2 (Dao et al., 2022) for efficient attention computation. FlashAttention doesn't change the mathematical result of attention — it computes the same output — but reorganizes the computation to minimize memory accesses to GPU HBM (High Bandwidth Memory) by tiling the attention computation into blocks that fit in SRAM. This results in 2-4× speedups and dramatically reduced memory usage during training.

The parallel MLP/MHA configuration means that within each transformer layer, the multi-head attention and feed-forward network are computed in parallel rather than sequentially. This is a minor architectural optimization that reduces latency without affecting quality, as both sub-layers operate on the same input and their outputs are added together.

7. Benchmark Results

7.1 HumanEval Performance

The headline result: Phi-1 achieves 50.6% pass@1 on HumanEval, a benchmark of 164 Python coding problems. For a 1.3B parameter model, this was extraordinary:

Code-Cushman-00112B33.5%~100B tokens

GPT-4 (reference)~1.8T (est.)67.0%Massive

Phi-1 at 1.3B parameters outperforms models 10-12× its size that were trained on 7-70× more data. This is the paper's most dramatic result and the primary evidence for the data quality hypothesis.

7.2 MBPP Performance

On MBPP (Mostly Basic Python Problems), another standard coding benchmark, Phi-1 achieves competitive results, though the margin over larger models is smaller. This suggests that the textbook-quality training is particularly effective for the kind of clean, well-defined problems in HumanEval, while larger models' broader training helps with the more varied problems in MBPP.

7.3 Unexpected Transfer: PyGame and TKinter

One of the most surprising findings is that Phi-1 generates functional PyGame and TKinter code despite never being explicitly trained on these libraries. The training data contains only standard Python with minimal external dependencies. The model appears to have learned general programming patterns that transfer to unfamiliar libraries — it understands function calls, parameter passing, and API usage patterns well enough to apply them to new contexts.

🤯
Transfer learning insight: This unexpected transfer suggests that textbook-quality code teaches not just specific syntax but general programming concepts — abstraction, composition, API usage patterns — that transfer across libraries. This is analogous to how a well-taught student can apply concepts to novel situations, even without having seen the specific example before.

8. Contamination Analysis

8.1 The Data Contamination Concern

A critical question for any code model evaluation: did the training data contain the benchmark problems? HumanEval problems are publicly available, and even aggressive filtering might not remove all traces. The paper addresses this with a careful contamination analysis.

8.2 Pruning Methodology

The authors remove any training example with >40% overlap (measured by ROUGE-L or exact match) with HumanEval problems. After pruning:

  • Approximately 40% of the training corpus is removed due to overlap
  • The remaining data (after aggressive pruning) is used for a retrained model
  • The pruned model's performance drops only modestly (to ~47%), still far above larger competitors

This suggests that while some contamination exists, the majority of Phi-1's performance comes from genuine learning of programming concepts, not memorization of benchmark solutions.

The GPT-4 classifier threshold controls how aggressively code is filtered. Too strict loses valuable data; too loose includes low-quality code:

The sweet spot is approximately the top 10% by educational quality. Interestingly, keeping too little data (2%) hurts because the model doesn't see enough examples, while keeping too much (100%) introduces noise that dilutes the signal.

10. Limitations

  • Narrow scope: Phi-1 is trained exclusively on Python code. It cannot generate code in other languages, and its natural language understanding is limited.
  • Counting failures: The model frequently fails at problems requiring exact counting (e.g., "how many elements satisfy condition X"). This is a known weakness of transformer models that persists even with high-quality training data.
  • Evaluation bias: HumanEval primarily tests clean, well-defined function completion. Real-world coding involves debugging, refactoring, and working with messy codebases — areas where Phi-1's advantages may not hold.
  • GPT-4 dependency: The filtering pipeline relies on GPT-4, creating a dependency on a proprietary model. The quality of filtering is limited by GPT-4's own biases and capabilities.
  • No open-source model weights: At the time of publication, Phi-1 weights were not released, limiting reproducibility.
  • Contamination concerns: Despite the pruning analysis, some residual contamination may exist, making the absolute performance numbers uncertain.

11. The Data Quality Principle: Broader Impact

Phi-1's central insight — that data quality matters more than scale — has had profound implications for the field:

  • Paper 04: SmolLM2 applied this principle to general language models, creating curated datasets (FineMath, Stack-Edu) that enable small models to compete with larger ones.
  • Microsoft's Phi-2 and Phi-3 extended the approach to larger models and broader tasks, achieving remarkable performance at 2.7B and 3.8B parameters.
  • The "textbook quality" concept — training on data that teaches rather than merely exposes — has become a standard principle in data curation for AI.
  • Synthetic data generation using LLMs to create training data for smaller models is now a mainstream technique (Alpaca, WizardLM, etc.).

"The lesson of Phi-1 is not that you can always replace scale with quality — it's that quality is the dimension most people were ignoring. When you fix data quality, you unlock capabilities that scale alone cannot provide."

12. Practical Implications

For practitioners, Phi-1 provides actionable guidance:

  • Data curation is cost-effective: Filtering a dataset for quality is orders of magnitude cheaper than training a larger model. A GPT-4 classifier run costs pennies per example.
  • Synthetic data complements real data: Generate textbook-style explanations and exercises to augment filtered code. The combination is more effective than either alone.
  • Small models are viable for production: A 1.3B model running on consumer hardware can provide coding assistance that was previously only available from 10B+ models.
  • Evaluate carefully: Contamination analysis is essential when reporting benchmark results. The >40% overlap threshold is a reasonable starting point.
🎯
Key takeaway: Phi-1 proved that a 1.3B model trained on 7B tokens of carefully curated data can outperform 15B models trained on hundreds of billions of tokens. The "textbook quality" filtering pipeline — using GPT-4 to identify pedagogically valuable code — is the primary innovation. This paper launched the data-centric AI movement and directly influenced SmolLM2, Phi-2/3, and the broader shift toward data quality as the primary lever for model performance.
